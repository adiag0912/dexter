# Dexter — Interview Prep

Notes I put together after reading the Dexter context pack, ahead of the second interview.

These are working documents meant to organise my thinking and seed the discussion — not a finished pitch.

## Contents

- **[dexter-overview.md](./dexter-overview.md)** — my read of the system: architecture, memory hierarchy, current engineering focus, strengths and risks I see.
- **[feature-workflows.md](./feature-workflows.md)** — a feature proposal: **Dexter Workflows**, voice-triggered parametric cross-app automations. A general-purpose evolution of the existing *templates / reusable actions* module that reuses every layer Dexter has already built.

## How to read these

Start with the overview to confirm we share the same mental model of the system, then move to the workflows proposal. Both are written to be skimmed — tables, diagrams, and short sections rather than long prose.

Feedback welcome — if I've misread part of the system or there's an angle you'd rather focus on, happy to adjust.
